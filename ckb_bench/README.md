# CKB-VM measurement layer for CellVG/HNDT

This directory provides the CKB-VM measurements consumed by the HNDT cost
model. It separates three concerns that were previously conflated:

1. primitive arithmetic calibration;
2. Merkle checkpoint authentication;
3. **state-chained** neural interval verification.

Predictive accuracy is intentionally out of scope.

## Benchmark modes

[src/main.rs](src/main.rs) supports:

- `relu`, `dot`, `gemm`, `conv` — primitive microbenchmarks;
- `merkle` — corrected authentication-path hashing;
- `merkle_access` — proof-data memory access without hashing;
- `lenet` — exact deterministic state transition verification on a 12-operator
  LeNet-5-shaped integer trace.

## Corrected Merkle authentication

The old benchmark hashed a fabricated sibling inside each proof level and then
hashed the parent, so it measured roughly two hashes per level while the README
claimed one. The corrected benchmark:

- receives precomputed sibling **digests**;
- performs exactly one parent CKB-Blake2b hash per proof level;
- orders `left || right` from the actual leaf-index bit;
- uses a canonical 13-state tree padded to 16 leaves for the depth-4 experiment;
- reconstructs and checks a known root;
- validates all 13 real leaf positions;
- measures proof-data access separately from parent hashing.

The canonical vectors are generated by
[generate_merkle_vectors.py](generate_merkle_vectors.py) and committed in
[src/merkle_vectors.rs](src/merkle_vectors.rs).

```bash
python generate_merkle_vectors.py --check
```

### Padding rule

The 13 real leaves are already-hashed 32-byte state commitments. The tree is
padded to 16 leaves with the all-zero 32-byte digest. Internal nodes are

```text
CKB_BLAKE2B256(left_digest || right_digest)
```

using CKB's `ckb-default-hash` personalization.

### Scope

`merkle` includes leaf-index ordering, one parent hash per level, and root
comparison. It does **not** claim to include real transaction witness syscalls
or decoding. Those must be measured separately.

## State-chained LeNet interval verifier

The old `lenet` mode executed independent synthetic operator-shaped workloads.
That was useful for arithmetic calibration but did **not** satisfy

```text
S_t = f_t(S_{t-1}).
```

The revised benchmark fixes this. [generate_lenet_vectors.py](generate_lenet_vectors.py)
creates a deterministic integer trace with the canonical LeNet-5 dimensions:

- Conv1: `1 x 32 x 32 -> 6 x 28 x 28`, 5x5;
- ReLU1;
- MaxPool1: `6 x 28 x 28 -> 6 x 14 x 14`;
- Conv2: `6 x 14 x 14 -> 16 x 10 x 10`, 5x5;
- ReLU2;
- MaxPool2: `16 x 10 x 10 -> 16 x 5 x 5`;
- Flatten: `400`;
- FC1: `400 -> 120`;
- ReLU3;
- FC2: `120 -> 84`;
- ReLU4;
- FC3: `84 -> 10`.

The input, quantized weights, biases, and all checkpoints `S0...S12` are fixed
and generated reproducibly. They are **not trained weights**; accuracy is not a
reported outcome.

For an interval `[i,j]`, the CKB program now:

1. loads the exact generated checkpoint `S_i`;
2. executes `f_{i+1},...,f_j` using the fixed quantized weights;
3. requires the resulting tensor to match the generated `S_j` exactly;
4. returns an error sentinel if dimensions or state equality fail.

This means measured `native_cycles` are now genuine interval-verification
costs under the benchmark semantics, not sums of unrelated kernels.

Generate/check the trace with:

```bash
python generate_lenet_vectors.py
python generate_lenet_vectors.py --check
```

The checked trace covers all 42 publication intervals of spans 1--4.

### What the interval cost includes

The `lenet` cycle count includes:

- copying the generated start checkpoint into VM memory;
- deterministic integer execution of the interval;
- exact comparison with the expected end checkpoint.

It still excludes:

- transaction witness syscalls/decoding;
- Merkle authentication (measured separately);
- complete Cell transition serialization;
- production model loading/economics.

Those components should be reported separately rather than hidden inside the
neural arithmetic number.

## Prerequisites

Linux/WSL2 is recommended.

```bash
rustup target add riscv64imac-unknown-none-elf
cargo install ckb-debugger --version 1.1.1
```

## Primitive and Merkle measurements

```bash
bash run_benchmarks.sh
```

Outputs:

- `logs/*.log`;
- `ckb_primitive_measurements.csv`.

Then from the repository root:

```bash
python experiments/fill_query_template_from_ckb.py
```

## State-chained interval measurements

```bash
bash run_lenet_intervals.sh
```

This measures all consecutive spans 1--4: `12 + 11 + 10 + 9 = 42` runs.

Outputs:

- `logs_lenet/*.log`;
- `lenet_interval_measurements.csv`.

Then:

```bash
python experiments/fill_interval_template_from_ckb.py
```

Unmeasured intervals remain unavailable; no interpolation is performed.

## Reliability rules

- use `ckb-debugger` cycle counts, not desktop wall-clock time;
- retain raw logs;
- never use demo values in the manuscript;
- never invent missing interval or zkVM costs;
- keep Merkle, witness/transaction, and interval-compute semantics explicit;
- only claim full-system baselines when the full external system is actually
  reproduced.
